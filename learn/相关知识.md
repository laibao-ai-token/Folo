Folo 启动指南（本地开发）

- 前置条件
  - Node.js 稳定版本（`.nvmrc` 为 `stable`）。建议使用 `nvm use` 切到稳定版。
  - pnpm 10.17.0（使用 Corepack 自动管理）
    - `corepack enable && corepack prepare pnpm@10.17.0 --activate`
  - 可选：iOS/Android 原生环境（仅在需要运行移动端时）

- 安装依赖（仓库根目录 `Folo/`）
  - `cd Folo`
  - `pnpm install`

- 启动方式（按需选择其一或几个并行）
  - 浏览器渲染层（推荐，最快路径）
    - `cd apps/desktop && pnpm run dev:web`
    - 访问 `http://localhost:2233`
  - Electron 桌面应用
    - `cd apps/desktop && pnpm run dev:electron`
  - SSR 分享站点（调试分享页/OG 图时需要）
    - `cd apps/ssr && cp .env.example .env && pnpm run dev`
    - 访问 `http://localhost:2234`
    - `.env` 中 `VITE_WEB_URL` 默认指向 `http://localhost:2233`
  - 移动端（Expo）
    - `cd apps/mobile && pnpm run dev`
    - iOS：`pnpm run ios`（或 `pnpm run ios:device`）
    - Android：`pnpm run android`

- 常用脚本（根目录）
  - 类型检查：`pnpm run typecheck`
  - Lint 修复：`pnpm run lint:fix`
  - 单测：`pnpm run test`

- 端口速览
  - Web（Vite）：2233（`apps/desktop` 渲染层开发）
- SSR：2234（`apps/ssr`）

- 常见问题
  - 找不到 pnpm：先运行 `corepack enable`，或 `corepack prepare pnpm@10.17.0 --activate`
  - 端口被占用：修改对应 `vite.config.ts`/`index.ts` 中端口或释放占用进程
  - 安装失败：先执行 `pnpm run reinstall` 清理所有 `node_modules` 后重装

说明：更多细节可参考仓库根目录的 `AGENTS.md` 与各子应用 `AGENTS.md`。

网页端全功能运行方式

- 方案 A（推荐）：Debug Proxy（在正式域名下跑本地代码，避免第三方 Cookie 限制）
  - 步骤
    - 启动渲染层：`cd Folo/apps/desktop && pnpm run dev:web`
    - 浏览器打开：
      - `https://app.folo.is/__debug_proxy?debug-host=http://localhost:2233`
      - 或 `https://dev.follow.is/__debug_proxy?debug-host=http://localhost:2233`
        （`debug-host` 省略时默认 `http://localhost:2233`）
  - 说明
    - 页面仍在 `*.follow.is` 域名下运行，调用线上 API（默认），登录/鉴权/跳转等功能与线上一致。
    - Vite 控制台会打印 Debug Proxy 入口，直接点开即可。
    - 本方案不要求本地启动 `apps/ssr`。

- 方案 B（纯本地联调）：渲染层 + SSR 同时跑
  - 启动渲染层：`cd Folo/apps/desktop && pnpm run dev:web`（端口 2233）
  - 启动 SSR：`cd Folo/apps/ssr && pnpm run dev`（端口 2234）
  - 可选：将 `apps/ssr/.env` 或 `apps/desktop/.env` 中的 `VITE_API_URL` 指向线上 `https://api.follow.is`，以免本地需要额外启动 API。
  - 注意：在 `localhost` 域名下直接调用线上 API，部分浏览器可能因第三方 Cookie 策略导致登录受限；若遇到登录问题，优先使用上面的 Debug Proxy 方案。
